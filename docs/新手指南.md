# 新手指南

先准备目标、简历和要用的平台，再让 Agent 带你初始化。不需要一次想清所有答案。

## 开始前准备什么

| 项目 | 要求 |
|---|---|
| 系统 | macOS 或 Linux，已安装 Git |
| Python | 3.9 或更新版本；引擎只用标准库 |
| Agent | 能打开本地仓库的 Claude Code、Codex 或其他 Agent |
| Node | 20.9 或更新版本；只在使用控制台时需要 |
| 浏览器 | 推荐 ego lite，以及 Agent 侧的 ego-browser skill |
| 平台 | 选好渠道，由你自己在浏览器里登录 |
| 简历 | 至少一份 PDF、Markdown、JSON、DOCX 或 TXT 文件 |
| 可选材料 | 作品集链接、已投递或正在沟通的机会、身份资料 |

[ego lite 官网](https://lite.ego.app/)提供安装入口。目前官方安装脚本只支持 macOS。
推荐它是因为 Agent 可以复用你自己浏览器里的登录态。安装浏览器后，还要确认当前 Agent
可用 `ego-browser` skill，且 `ego-browser` 命令在 PATH 上。
不装也能准备工作区，但 Agent 只能用未登录浏览器读公开页面，很多招聘平台内容不可见。
Linux 用户可以先用 CLI 和公开页面；Agent 不会擅自安装系统软件或更换浏览方式。

可选平台包括 BOSS直聘、猎聘、LinkedIn、Indeed、前程无忧、公司官网/ATS。
只登录你打算使用的平台。登录、密码、验证码由你自己处理；不要发给 Agent。
邮箱和 Slack 的求职消息巡检需要另外确认范围，不包含在岗位搜索授权中。

把简历放进 `03-简历/`；子目录也可以。README 不算简历。
Agent 只读原始事实；改写投递材料前会让你确认。不要放身份证件、密码或其他秘密。

## 第一次对话会问什么

在仓库里对 Agent 说“帮我初始化”。它按[首次使用访谈](../00-工作流系统/runbooks/首次使用.md)只补问缺失信息，通常每次 2–4 个问题。
你一次给出多个阶段的答案时，可以合并复述、一次确认后统一写文件；已有明确写入授权不重复确认，跳过或沉默不算确认：

1. 你的系统、Agent 和环境缺口；想先看演示还是直接开始？
2. 想找什么岗位方向和级别？接受哪些城市、远程和通勤范围？
3. 偏好什么行业、公司类型（外企、内资或不限）？
4. 薪资底线和期望各是多少，按什么口径？最早什么时候到岗？
5. 哪些因素最重要？技术与经验 30、工时与生活 25、成长 20、薪资 15、文化与休假 10 是示例权重。你可以增删，合计须为 100。
6. 推荐阈值是否采用示例的匹配分 75、证据覆盖率 80、淘汰上限 50？是否优先已核实的外企？未回答的 `foreign_first` 写 null，评分照常可用，不按所有制排序。分数不是录用概率。
7. 有哪些一票否决条件，例如外包驻场、单人团队、长期 996？
8. 是否准备 ego lite？用哪些平台，哪些已经登录？
9. 放入哪些简历、作品集或已有机会？是否愿意选填 identity.json？
10. 是否使用控制台和定时任务？

不想答的项保留 null / 未定。访谈记录放在个人目录的 `onboarding.json`。
现有评分格式要求明确的权重、阈值和至少一条硬线；这些未定，或明确没有硬线时，
Agent 会说明评分暂未准备好，不会编一套答案来通过校验。`foreign_first` 支持 true、false、null 或缺省；
只有 true 启用同组外企优先，null/缺省保留未定含义、不阻塞评分，不代填 true/false。到岗时间等补充信息不硬塞进评分格式。

## 手动开始与检查

先复制仓库并进入目录：

```bash
git clone https://github.com/LeiZiKang/jobflow.git
cd jobflow
```

从仓库根目录运行：

```bash
python3 00-工作流系统/bin/jobflow.py init
python3 00-工作流系统/bin/jobflow.py doctor
```

首次 init 仅生成状态和示例 goals。doctor 此时通常退出 1：缺目标定制、简历和渠道确认。
让 Agent 完成访谈，或按 `00-工作流系统/examples/screening/goals.example.json` 的结构编辑个人 goals。
不要只改排版，doctor 会比较 JSON 内容。确认渠道后，复制默认模板到个人目录再编辑：

```bash
PROFILE_DIR="${JOBFLOW_PROFILE_DIR:-$HOME/.config/jobflow/profile}"
mkdir -p "$PROFILE_DIR"
# -i 会在已有文件时询问，避免直接覆盖
cp -i "00-工作流系统/config/search_channels.json" "$PROFILE_DIR/search_channels.json"
# 仅在需要邀约巡检且已确认范围时复制
cp -i "00-工作流系统/config/inbound_sources.json" "$PROFILE_DIR/inbound_sources.json"
```

裁剪 `required_daily` / `sources`，修改查询词、地域、覆盖下限和官网名单。
把 `<你的岗位关键词>`、`<目标城市或远程>`、薪资和硬线等模板占位按访谈填写，不能原样沿用。
官网名单也是占位；每日公司数 null 表示未确认，需确认实际覆盖下限。不要修改 git 跟踪的 config 模板来保存个人偏好。
未决定渠道时，不要创建 search_channels 覆盖文件；明确只用手动输入岗位时，可确认空清单。

```bash
python3 00-工作流系统/bin/jobflow_screening.py --validate-profile
python3 00-工作流系统/bin/jobflow.py config search_channels.json
python3 00-工作流系统/bin/jobflow.py doctor --json
./00-工作流系统/scripts/check-all.sh
```

doctor 的 **5 项必需检查**：Python、已 init 的 state、有效且不同于示例的 goals、简历、个人渠道覆盖文件。
全部 ok 才返回 0，否则返回 1。Node、控制台依赖、ego-browser、identity.json 缺失只记 warn。
控制台依赖必须同时有可执行的 `console/node_modules/.bin/tsc` 和 `.bin/next`；
空目录或残缺安装会 warn，需重新运行 `(cd "console" && npm install)`。doctor 与 check-all 使用同一检查，依赖就绪不等于构建通过。
doctor 不输出 goals 或 identity 正文，也不会登录平台；config 命令会显示所选渠道配置，请勿贴到公开 issue。

**准备好了** = doctor 必需项全绿 + check-all 通过。它不证明简历内容真实、平台已登录或所有渠道可用。
建议第一步是手动跑一次只读岗位检索，确认覆盖与阻塞后再考虑定时任务。

## 数据放在哪

| 内容 | 位置 |
|---|---|
| 目标、渠道、访谈记录、可选身份 | `JOBFLOW_PROFILE_DIR`，默认 `~/.config/jobflow/profile/` |
| 个人渠道覆盖 | 上述目录的 `search_channels.json`、`inbound_sources.json` |
| 默认渠道模板 | `00-工作流系统/config/`；个人文件不存在时才读取 |
| 简历 | `03-简历/` |
| 进度、证据、审批 | `00-工作流系统/state/`、`evidence/`、`approvals/` 等 |
| 求职报告 | `05-检索报告/` |
| 本地服务运行数据 | `JOBFLOW_RUNTIME_DIR`，默认 `~/.local/state/jobflow` |

个人目录必须在仓库外，文件不能通过符号链接跳出该目录。覆盖文件损坏会报错，不回退到模板。
建议个人目录权限 0700，文件权限 0600。换机器时另行迁移个人目录，定时触发器使用同一环境变量。
仓库中的用户数据默认被 git 忽略。若要版本化，只在私有仓库里调整忽略规则，不要提交到公开仓库。

## 常见问题

**我只想先看效果。**
运行 `python3 00-工作流系统/bin/jobflow.py init --demo`。
看完后用 `init --force` 重置。旧核心状态会备份到 `00-工作流系统/.init-backup-*`；
演示清单内的业务文件会删除，不要在演示文件里写真实数据。个人配置会保留。

**doctor 说 goals 还没改，但我已经 init 了。**
init 复制的是中性占位模板。需要按你的目标改内容，并通过现有 profile 校验。
只修改空格、缩进或键顺序不算定制。

**不想提供身份信息，能开始吗？**
可以。identity.json 只在准备投递材料时按需提供，不影响检索和 doctor 就绪判定。

**没装 Node 或控制台依赖，能开始吗？**
可以先用 CLI。需要控制台时再安装 Node 20.9+，运行 `cd console && npm install`，
回到仓库根目录执行 `./00-工作流系统/local-control/start.sh`，打开 `http://127.0.0.1:8788`。
不要直接 `npm run dev`，启动脚本会连接本地服务。

**ego-browser 已通过，平台却仍要求登录。**
检查通过只代表命令存在。skill 是否可用、登录是否有效要在当前 session 核实。登录由你处理。

**check-all 失败怎么办？**
先确认 init 已完成，再看第一个报错；把不含个人内容的错误交给 Agent。不要为了全绿伪造数据。
未安装控制台依赖时 TypeScript 检查会跳过并告警，完整控制台验证需先安装依赖。

**怎样设置定时任务？**
先手动跑通，再读 [调度说明](../00-工作流系统/adapters/SCHEDULED_COMMON.md)。
使用 [Claude Code](../00-工作流系统/adapters/CLAUDE_CODE_SCHEDULED.md) 或
[Codex](../00-工作流系统/adapters/CODEX_SCHEDULED.md) 对应说明。对外动作仍须另行批准。
