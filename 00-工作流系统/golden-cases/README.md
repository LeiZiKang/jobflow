# Golden cases

这些案例用于校准备用 Decider 的判断质量，不要求得出一模一样的措辞，但不得违反事实与授权边界。
机器可读定义在 `cases.json`，案例公司和证据路径均为虚构或模板路径。

1. **组织匹配**：候选分数不最高，但组织成熟、文化画像更符合长期目标；外部 ATS 需要多级人工审批，最终只有成功页才能闭环。
2. **新证据反转**：初筛看似匹配，深挖发现团队规模和长期融资风险后下调。新证据必须能推翻旧评分。
3. **工作强度硬线**：技能和薪资匹配，但多条工时证据触发 WLB 硬线，不能因品牌或高薪淡化。
4. **猎头未披露雇主**：可把岗位真实性、雇主真实性和匹配度分开评估；必须补真实雇主与用工主体。
5. **计划与执行**：存在投递指令但没有平台状态、截图和记录时，只能判定未验证，不能算已投。

以后每次出现能显著提高接管质量的新型决策，把脱敏后的规则和证据路径加入这里，不复制整个 session。

校验案例定义：

```bash
python3 00-工作流系统/bin/jobflow.py golden-check
```

跨模型回归时，让被测 Decider 输出：

```json
{"answers":[{"case_id":"...","decision":"...","rules_applied":["..."]}]}
```

再运行：

```bash
python3 00-工作流系统/bin/jobflow.py golden-check --answers /path/to/answers.json
```

评分只检查决策枚举和规则集合，不依赖措辞相似度。
