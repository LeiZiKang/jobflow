# Runbook：电话初筛与面试准备

## 目标

让任一 Agent 只靠仓库为一场面试准备事实一致、可直接使用的材料，并在面试后把真实进展回写。
不替用户编经历、离职原因、薪资依据或技术能力。

## 面试前

1. 从 `state/applications.json` 找到 application ID、当前阶段、简历版本和证据。
   如果应用已进入 `interviewing` / `offer`，先打开其生成的
   `04-面试/公司/<application-id>/index.html` 总览，不要从零散文件猜当前状态。
2. 读取对应岗位档案、实际投递的简历/Cover Letter、`02-策略/电话面试口径.md`。
3. 列出三类内容：
   - 已核实且可直接说的事实；
   - JD 要求但用户明确没有的能力；
   - 仓库缺事实、必须问用户的问题。
4. 技术缺口统一用封闭表述：
   - 「这块我没有生产经验」；
   - 「我做过的是 ___」；
   - 「如果它是核心要求，我会按 ___ 上手」。
5. 准备三个必问：薪资范围、团队/职责、后续轮次与时间。
6. 面试环境不合适时先改约；不要一边做其他事一边接电话。

## 事实边界

- 离职原因、项目职责、技术深度只按仓库里已核实的口径说；没有记录的不推测、不美化。
- 只有测试或 demo 级别的经验，不得包装成生产经验；没有证据的“独立负责”不得写成独立负责。
- 薪资相关只说用户已确认的事实，不把 Agent 推测写成公司定薪结构。
- 简历上合并展示的经历，回答时要按真实公司与真实月份拆开说。

## 面试后

1. 当天在 `04-面试/公司/<application-id>/rounds/` 记录：时间、轮次、面试官、全部问题、
   用户实际回答、对方给的信息、结果。
2. 不把 Agent 建议混成用户的原始记录；分节标注。
3. 回写 `applications[].case`：公司明确反馈、用户观察/自我复盘、Agent 分析分别入栏；
   未记录的实际回答保持 `not_recorded`。
4. 更新 `task_queue.json` 中下一次检查日期/前提；进入 `interviewing` 前 Case 必须已建好。
5. 运行 `jobflow.py render-views --write` 生成 Case HTML、投递记录与 README，再生成 brief 并 validate。
6. 感谢信或跟进只起草；发送前按审批协议取得一次性批准。

## 完成标准

- 应用状态、投递记录和面试记录一致。
- Case HTML 能从 Dashboard 打开，并清楚分开公司反馈、用户复盘和 Agent 分析。
- 被问倒的问题进入下一轮准备清单。
- 未核实事实明确留白，而不是由 Agent 自动补全。
- 对方承诺的时间点变成仓库中的下一任务或 `not_before`。
