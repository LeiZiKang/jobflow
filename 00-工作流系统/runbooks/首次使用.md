# 首次使用：Agent 引导访谈

适用于 state 不存在，或 `jobflow.py doctor` 必需项未齐的工作区。
给用户看的清单：[新手指南](../../docs/新手指南.md) / [English](../../docs/getting-started.en.md)。

下面的阶段是信息清单，不是必须逐题走完的问卷。只补问缺失信息，通常每次 2–4 个问题。
用户一次性提供大量信息时，可跨阶段合并复述答案、未定项和拟写文件，一次确认后统一写入；
不要求每阶段单独确认。用户已明确授权的具体写入不再重复索要确认，授权范围不扩大。
用户说“先跳过”或没有回应不算确认；可以继续收集独立信息，未获确认的文件暂不写。
已确认的内容不用重问。已有文件先读取，局部更新，不覆盖其他资料。
不编造目标、经历或偏好；不想答的项记 `null` / “未定”，不能把示例当作答案。
确认初始化只授权本地准备，不授权登录、投递、发送或改平台资料。

## 0. 环境

```bash
python3 00-工作流系统/bin/jobflow.py doctor
```

未通过是首次使用的正常状态。Python 无法运行时用 `python3 --version` 检查。
Python 至少 3.9；Node 至少 20.9，仅控制台需要。缺 Python / Node 只提示安装要求，
不要擅自安装系统级软件。`--json` 返回结构化结果，不输出目标或身份正文。

这一轮问：

1. 你用 macOS 还是 Linux？打算用哪个 Agent？
2. 缺失的可选组件先跳过，还是稍后准备？

复述环境缺口与影响。本阶段不写个人文件。

## 1. 演示还是直接开始

这一轮问：

1. 想先看演示，还是直接开始空工作区？
2. 若已有状态，要继续补齐资料，还是确认备份并重置？

确认后只执行所选命令：

```bash
python3 00-工作流系统/bin/jobflow.py init --demo
# 或直接开始
python3 00-工作流系统/bin/jobflow.py init
```

演示全部是虚构数据。看完并确认重置后运行：

```bash
python3 00-工作流系统/bin/jobflow.py init --force
```

旧 state、events、evidence、approvals 和 brief 会备份到 `00-工作流系统/.init-backup-*`。
演示清单列出的业务文件会被移除；不要直接在演示文件里填写真实资料。
个人目录的 goals 和渠道配置不会被重置。已有真实工作区只缺资料时，不要用 force。

## 2. 求职目标

信息不足时分两轮补问，已有答案跳过：

1. 想找什么方向和级别？有哪些岗位关键词？
2. 哪些城市能接受？远程和通勤有什么要求？
3. 行业或公司类型有偏好吗，例如外企、内资或不限？

然后问：

1. 薪资底线与期望各是多少？币种、税前/税后、月薪/年薪、薪资月数如何算？
2. 最早什么时候到岗？不确定可以留空。
3. 有没有投递数量目标？没有就不设。数量指累计已验证投递，不是必须完成的默认任务。

复述并确认后，把答案保存到个人目录 `onboarding.json`，不放进公开配置。
这是访谈记录，不是评分输入。可使用 `role_direction`、`level`、`locations`、`remote`、
`commute`、`industries`、`company_type`、`salary_floor`、`salary_target`、`salary_basis`、
`earliest_start` 等字段；未回答用 null。后续阶段确认的答案也在这里记录。

数量目标未设置时，保留 `00-工作流系统/state/current.json` 中 `metrics.diagnostic_sample_target`
和 `metrics.gap_to_target` 为 null；不代填 15 或 0。仅在用户确认数量后填写非负整数目标，
把 gap 更新为 max(目标减已验证数量, 0)，再运行 `python3 00-工作流系统/bin/jobflow.py brief --write`
和 `python3 00-工作流系统/bin/jobflow.py render-views --write`。demo 的 15 是虚构演示目标。

个人目录通过 `jobflow_profile.profile_directory()` 解析；默认 `~/.config/jobflow/profile/`，
可由 `JOBFLOW_PROFILE_DIR` 覆盖，必须在仓库外。见 [PRIVATE_PROFILE.md](../PRIVATE_PROFILE.md)。

## 3. 评价因素与权重

以 `00-工作流系统/examples/screening/goals.example.json` 为结构起点，先展示默认维度：

| 维度 | 默认权重 |
|---|---:|
| 技术与经验（技术匹配） | 30 |
| 工时与生活 | 25 |
| 成长环境 | 20 |
| 薪资匹配 | 15 |
| 文化与休假 | 10 |

这一轮问：

1. 哪些维度保留、删除或新增？每项怎样才算好、一般、不合适？
2. 权重怎样分配？每项必须大于 0，合计 100；不计分的维度删除。
3. 推荐阈值采用示例值，还是调整？示例是最低匹配分 75、证据覆盖率 80、淘汰上限 50。
4. 同一推荐组内是否优先已核实的外企？这是可选的 `foreign_first`：未回答写 null，不替用户选 true/false，也不因此阻塞评分。

分数是有证据支持的匹配程度，不是录用概率。硬线未知、证据不足时仍是待核实。
阈值均为 0–100，`reject_below` 不得高于 `recommend_at`。
确认后记录权重、阈值、每项 rubric 和排序偏好。把已确认的方向、薪资等落实到 rubric；
模板中的 `<你的岗位方向与级别>`、`<你的薪资底线、期望与计薪口径>`、`<你认可的成长环境>`
须按访谈填写；不沿用占位或猜答案。下一阶段确认硬线后再写完整 `goals.json`。

## 4. 硬线

这一轮问：

1. 哪些情况直接不考虑，例如外包驻场、单人团队、长期 996？
2. 地点、薪资底线或到岗时间里，哪些也是硬线，哪些可以谈？

复述具体条件，确认后写入 `goals.json` 的 `hard_rules`，并写入上一阶段的评分配置。
不要把示例硬线自动套给用户。命中硬线时高分不能抵消；没有证据不能判通过。

当前 goals 契约只支持 `schema_version`、`foreign_first`、`dimensions`、`hard_rules`、
`thresholds`，不要直接加到岗时间等额外字段。`foreign_first` 可以是 true、false、null 或缺省；
只有 true 启用同组外企优先，false/null/缺省均不按所有制分层排序，null/缺省保留未定含义。
未回答时写 null。权重和阈值仍要求具体值，
硬线要求至少一条非空规则；用户未定或明确没有硬线时，保留访谈中的 null / 未定，
说明当前评分契约尚不能表达，不伪造硬线或默认值来通过校验，暂不宣布准备完成。
待讨论的草案留在 `onboarding.json`；除允许未定的 `foreign_first` 外，不把缺失评分参数当成已确认配置。
硬线中的 `<目标城市或远程：用户确认的地点硬线>` 等占位必须按用户确认内容填写；不适用的规则删除。

```bash
python3 00-工作流系统/bin/jobflow_screening.py --validate-profile
```

## 5. 浏览器与平台

这一轮问：

1. 是否装了 [ego lite](https://lite.ego.app/)？是否愿意准备它？
2. 想用哪些平台：BOSS直聘、猎聘、LinkedIn、Indeed、前程无忧、公司官网/ATS，或其他？
3. 哪些平台已由你自己在浏览器里登录？哪些需要稍后处理？
4. 每个渠道要查哪些查询组、多少页或何时停止？官网每日公司数是否需要设下限？

推荐 ego lite 是因为它能复用用户自己浏览器里的登录态。目前官方安装脚本只支持 macOS；
装好浏览器后，Agent 侧还需要 `ego-browser` skill。doctor 只检查 PATH 上是否有命令，
不验证 skill 已启用，也不证明平台已经登录。
不装时，Agent 只能用未登录浏览器看公开页面，很多平台内容不可见；先说明限制，由用户决定。
所有登录、验证码、账号密码都由用户自己处理，Agent 不触碰，也不绕过。

确认后，复制 `00-工作流系统/config/search_channels.json` 到个人目录，再按选择裁剪 `required_daily`，
根据访谈填写 `<你的岗位关键词>`、`<目标城市或远程>`、覆盖下限、官网名单和 completion 说明，
不沿用模板占位；官网每日公司数 null 表示尚未确认，不能当作自动设定的下限。
渠道确认不等于平台访问已验证，也不等于投递授权。尚未决定渠道就不创建该覆盖文件。
若用户明确只用手动提供的岗位，可确认空渠道清单，并说明不能自动检索。

需要邀约巡检时，再问 2 个问题：要检查哪些平台收件箱？是否授权求职相关邮箱/Slack？
确认后复制 `00-工作流系统/config/inbound_sources.json` 到个人目录，裁剪 sources；搜索授权不包含收件箱授权。

统一读取有效配置，不直接读默认模板：

```bash
python3 00-工作流系统/bin/jobflow.py config search_channels.json
python3 00-工作流系统/bin/jobflow.py config inbound_sources.json
```

个人覆盖优先；没有覆盖才回退到仓库模板。模板回退不表示已确认渠道。
覆盖文件损坏或链接不安全时报错，不静默回退。config 输出可能包含个人偏好，不要贴到公开 issue。

## 6. 初始文件

这一轮问：

1. 哪份简历作为事实来源？请放进 `03-简历/`，PDF / Markdown / JSON / DOCX / TXT 都可以。
2. 有作品集链接或补充材料吗？可以暂不提供。
3. 有正在沟通或已投递的机会吗？是否同意逐条核对后登记？
4. 是否愿意现在准备 `identity.json`？只在准备投递材料时需要，可以跳过。

Agent 只读简历，不改事实。确认已有机会的来源、时间和真实状态后，才登记 inbound/application。
文件存在不等于简历内容已核实；README 不算简历。复述文件清单和选填项，确认后写访谈记录。

## 7. 可选组件

这一轮问：

1. 要现在使用控制台，还是先用 CLI？
2. 要配置定时任务，还是先手动跑一次？

确认使用控制台后：

```bash
cd console && npm install
cd ..
./00-工作流系统/local-control/start.sh
```

浏览器打开 `http://127.0.0.1:8788`。macOS 也可双击根目录启动器。
定时任务按 `adapters/SCHEDULED_COMMON.md`、`CLAUDE_CODE_SCHEDULED.md` 或
`CODEX_SCHEDULED.md` 配置；外部触发器也须继承同一 `JOBFLOW_PROFILE_DIR`。
确认运行时间、时区和范围后才配置；定时任务不授权投递、发送、登录或改资料。

## 8. 准备好了

```bash
python3 00-工作流系统/bin/jobflow.py doctor
./00-工作流系统/scripts/check-all.sh
```

只有 doctor 必需项全部 ok（退出码 0），且 check-all 通过，才说“准备好了”。
warn 不影响 doctor 退出码，仍要解释影响。控制台依赖只有 `.bin/tsc` 与 `.bin/next`
都存在且可执行才算就绪；空 node_modules 或不完整安装需重新 npm install。依赖通过不代表构建通过。准备好了不代表平台均可访问或已授权外部动作。

最后复述目标、权重、硬线、渠道、简历与其他文件、未定项和剩余警告，问：

1. 这份准备结果是否准确？此前已合并确认且无变化的内容不用重复确认。
2. 是否现在按所选渠道手动跑一次只读岗位检索？

用户确认后才按 `runbooks/每日岗位检索.md` 开始；无需再次初始化。
更新结构化状态或说明本阶段无需更新；新记忆只能通过 `memoryctl.py` 提 proposed。
