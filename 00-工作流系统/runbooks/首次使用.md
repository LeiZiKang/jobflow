# 首次使用

这个 runbook 给 Claude Code、Codex 或其他 Agent 用。目标是带新用户完成初始化，不替用户安装系统软件，不写虚假目标。

## 1. 检查前置条件

先检查：

```bash
python3 --version
node --version
```

还要确认当前 session 有没有能复用用户登录态的浏览器 skill，例如 `ego-browser`。没有就明确告诉用户：后续只能看未登录公开页面，大部分招聘平台内容可能不可见。

缺 Python、Node、浏览器 skill、Xcode Command Line Tools 时，只说明缺什么和影响。不要擅自安装系统级软件。

## 2. 问用户初始化方式

问一个短问题：

```text
你想先看演示数据，还是直接初始化空工作区？
```

- 演示：运行 `python3 00-工作流系统/bin/jobflow.py init --demo`。
- 空工作区：运行 `python3 00-工作流系统/bin/jobflow.py init`。

如果用户看完演示后要清空，运行：

```bash
python3 00-工作流系统/bin/jobflow.py init --force
```

## 3. 收集求职目标

初始化会创建仓库外目标文件：

```text
~/.config/jobflow/profile/goals.json
```

结构参考：

- `00-工作流系统/examples/screening/goals.example.json`
- `00-工作流系统/examples/screening/goals.schema.json`
- `00-工作流系统/PRIVATE_PROFILE.md`

通过对话逐步收集，不要一次甩二十个问题。每次问三到五项即可。

优先问：

- 方向和岗位关键词。
- 城市、远程、通勤边界。
- 薪资底线和期望。
- 硬线，例如不接受外包驻场、不接受单人团队、不接受长期高强度加班。
- 评分维度权重，例如技术匹配、工时、成长、薪资、文化。

身份信息在 `identity.json`。只有用户愿意时才填。检索和评分不需要身份信息。

## 4. 校验目标配置

写完目标后运行：

```bash
python3 00-工作流系统/bin/jobflow_screening.py --validate-profile
```

如果失败，按错误修 `goals.json`。不要拿示例目标冒充用户目标。

## 5. 简历

请用户把简历放进：

```text
03-简历/
```

支持 PDF、Markdown、JSON 或用户已有格式。

Agent 只读简历，不改写事实。需要为某个岗位定制材料时，先列出拟调整点，等用户确认。

## 6. 渠道

打开：

```text
00-工作流系统/config/search_channels.json
```

和用户确认启用哪些平台，例如 BOSS直聘、猎聘、LinkedIn、公司官网。

提醒用户：需要自己在浏览器里登录这些平台。Agent 不输入账号、密码、验证码。

## 7. 可选：定时任务

如果用户想配置定时任务，读：

- `00-工作流系统/adapters/SCHEDULED_COMMON.md`
- `00-工作流系统/adapters/CLAUDE_CODE_SCHEDULED.md`
- `00-工作流系统/adapters/CODEX_SCHEDULED.md`

定时任务默认只读，不包含投递、发送、登录或改资料。

## 8. 可选：控制台

第一次用控制台：

```bash
cd console
npm install
cd ..
```

启动：

```bash
./打开本地求职控制台.command
```

或：

```bash
./00-工作流系统/local-control/start.sh
```

浏览器打开 `http://127.0.0.1:8788`。

## 9. 最后检查

运行：

```bash
./00-工作流系统/scripts/check-all.sh
```

然后向用户复述：

- 当前求职目标。
- 已启用渠道。
- 已放入的简历材料。
- 当前不能做什么。
- 下一步建议：先手动跑一次岗位检索，读 `00-工作流系统/runbooks/每日岗位检索.md`。
