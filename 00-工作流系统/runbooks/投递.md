# Runbook：投递

1. 只处理任务和批准中明确列出的岗位，不能自行增加。
2. 投前重新核实 JD 仍在招、公司/岗位/渠道和简历版本。
3. 打招呼语、Cover Letter、附言等先生成草稿；需要用户批准完整原文。
4. 凭据、验证码、资格声明、隐私声明和最终提交按宪章交还用户。
5. 表单准备完成记为 `application_prepared`，不能写成已投。
6. 执行提交后先记 `submitted_unverified`。
7. **提交后立刻截图留档**（见下）。没有截图不能记 `submitted_verified`。
8. 只有看到成功页、平台状态或确认邮件，**并且**截图已归档进 manifest，
   才能记 `submitted_verified`。
9. 更新应用状态、跟进日期、证据 manifest、业务记录和 brief，再运行校验。
10. 按 `runbooks/电话准备.md` 为该具体岗位生成并登记电话初筛脚本，在工作台验证可打开。尽量随发送包提前准备；投递后缺脚本会由 sync-progress 列待办，不能把“有通用口径”当作岗位专属脚本已完成。

## 投递后截图留档

**为什么**：平台侧的证据会消失——JD 下架、会话被清、状态页刷新之后就取不回来了。
一句文字回读只是 Agent 的转述，截图才是能复核的原件。证据等级见宪章 §7。

### 谁来截

最终提交由用户本人执行（宪章 §6），所以截图有两种合法来源，**manifest 里必须写明是哪种**：

- **用户本人在提交现场截。**最可靠，成功页往往只出现一次。
- **Agent 事后用 ego-browser 回读再截。**只能证明"当前状态"，不能证明"提交瞬间"，
  `note` 里要写清是事后回读。

Agent 不得为了凑证据去操作账号或重新提交。

### 截什么

按这个优先级，能拿到几张拿几张：

1. **成功页 / 提交确认弹窗**——最有力，只出现一次，优先抢
2. **平台上该岗位的投递状态**（已投递 / 已读 / 已回复）
3. **确认邮件**
4. **会话记录**（猎聘、BOSS 这类聊天渠道）

截图要能自证：**必须包含公司名或岗位名**，以及平台自己的状态文字。
裁成只剩一个"发送成功"绿勾的图没有价值。

### 存哪

```
assets/投递截图/<application-id>/<序号>-<说明>.png
```

例：`assets/投递截图/app-20260101-acme-ios-00000001/01-平台会话-已读.png`

按 application_id 分目录，和 `evidence/<application-id>/` 对齐。

### 怎么归档

截图落盘后用 `--proof` 挂进 manifest，`kind` **必须以 `screenshot` 开头**：

```bash
python3 00-工作流系统/bin/jobflow.py evidence-record \
  --application-id app-20260101-acme-ios-00000001 \
  --task-id <对应的投递任务 ID> \
  --operation application_submit \
  --result verified_success \
  --actor 用户 --backend ego-browser --auditor <你自己> \
  --platform 猎聘 \
  --approval-id approval-XXXX \
  --platform-readback "平台原文照抄，不要转述" \
  --proof "screenshot_success_page=assets/投递截图/<app-id>/01-成功页.png" \
  --proof "screenshot_platform_status=assets/投递截图/<app-id>/02-投递状态.png" \
  --note "谁截的、什么时候截的、是现场还是事后回读"
```

`evidence-record` 会自己算 SHA-256 和字节数写进 manifest，`evidence-verify` 之后
每次都会重算比对——**图被改过或被删掉，校验就会红**。

### 校验（两道）

1. **记录时**：`evidence-record` 对 `application_submit` + `verified_success`
   直接拒绝没有截图的调用。缺图要当场炸——等事后才发现，平台证据往往已经没了。
2. **校验时**：`jobflow.py validate` 按**整条投递**查，要求它的 manifest 里
   至少有一处 `screenshot*` proof artifact。`check-all.sh` 和 pre-commit 都会跑。

第二道故意按投递查而不是按单份 manifest 查：**已经写好的 manifest 不要回去改**
（那是伪造当时的证据等级）。补救办法是用现在拿到的截图**追加一份新 manifest**，
`note` 里写清是事后回读补的。

带 `legacy_evidence: true` 的历史投递豁免（宪章不追溯伪造历史证据）。
**新投递不要去打这个标记来绕过检查**——那同样是在伪造证据等级。
